# Проверка профиля Rhino E71 через main

Профиль E71 задаёт положение правой кисти относительно канонической модели
носорога, шесть команд preshape и закрытие за 12 шагов / 2 секунды, затем
1 секунду settle. Источник — коммит `e5da24ff94559913d3545d87e889f31fd71659c9`
из PR №9. Числа лежат в `hack_motion/profiles/rhino_e71.json`, вместе с
идентификатором рецепта и SHA256 исходных каталога и результата.
Лимит усилия 0.6 и подъём TCP на 47 мм взяты из запроса E71.
Новые presets требуют явный `Hand.force` в диапазоне `(0, 0.6]`.

В E71 измеренный подъём составил 45.633 мм. Это исходное свидетельство
работоспособности хвата. Новый исполнитель использует штатные `MoveTcp` и
`Hand` из main и требует собственной физической проверки. Геометрия коллизий,
подготовка рук и траектории main отличаются от исполнителя PR №9.

`hack_brain.recorded_pick.pick_recorded` выполняет одну попытку. После ready и
после pregrasp повторно получает свежую каноническую RGB-D-позу. Все шесть
пальцев движутся одновременно по записанной последовательности. Подъём
строится от измеренного TCP после закрытия. Интервал удержания увеличен до
5 секунд для этой проверки. Клиент сохраняет JSONL с позами, командами,
состояниями пальцев и wrist wrench. Результат `commands_completed` обозначает
окончание команд. `physical_hold_confirmed` остаётся `null` до независимого
просмотра записи или проверки физической трассы.

## Запуск на выделенном стенде

Нужны свежий simulator, обе пустые кисти, доступный Rhino и собственная
блокировка стенда. Начальную раскладку и seed записывают в журнал прогона.
Образ разработки и RGB-D weights переиспользуются со стенда по `docs/SERVER.md`.
Команды выполняются из корня этой ветки.

```bash
export NSSR_HOST=nssr-rtx6000
export NSSR_WHO=rhino-profile
bash tools/remote.sh status
bash tools/remote.sh sim start sort3 --pool 4 --seed 1
bash tools/remote.sh dev --timeout 900 -- \
  'bash tools/stage_perception_rgbd.sh && bash tools/run_recorded_probe.sh --out data/rhino-camera-1.jsonl'
bash tools/remote.sh fetch work/rhino-profile/nssr-sol-team-049/data/rhino-camera-1.jsonl
bash tools/remote.sh sim stop
```

Сначала сверить `status` и запущенные контейнеры через `gpu`. При занятом стенде
дождаться его освобождения. Владелец прогона отдельно пишет видео simulator.
Проба завершается с закрытой кистью. После сохранения записи собственный
эпизод останавливают через `sim stop`.

Для сравнения с известной позой инструмент принимает `--known-pose FILE`.
Файл готовится для текущего отладочного эпизода, из канонической позы модели,
преобразованной в pelvis. Формат содержит `object_name` с полным именем Rhino,
`frame_id` равный `pelvis`, `reference_frame` равный `canonical_rgbd_model`
и матрицу `T_pelvis_object` 4×4.
Центр bounding box для этого преобразования непригоден. Файл используется
только инструментом в `tools/`. Collision world по-прежнему запрашивается у
perception. Оба режима запускают в отдельных свежих эпизодах с одинаковым seed.

## Приёмка

Для каждого режима записать исходную позу, версию кода, ошибки TCP и результат
подъёма. По видео или независимой физической трассе проверить отрыв предмета
от стола и нахождение в кисти все 5 секунд. Команды пальцам и показания
`object_detected` сохраняются как дополнительные измерения. При перекрытии
объекта и отсутствии независимого наблюдения результат остаётся неизвестным.

Первая серия — три повтора одной исходной позы в обоих режимах. Затем
зафиксировать отдельные старты с изменением XY и yaw и проверить их без
изменения профиля между попытками. Если повтор с известной позой проходит, а
RGB-D — нет, сравнить позу, возвращённую perception, с контрольной позой.
Brother на том же main служит проверкой исправности штатного пути исполнения.

На 10 ноября локально прошли 182 теста, 6 пропущены из-за отсутствия ROS.
Проверки охватывают композицию поз, порядок закрытия, свежесть наблюдений,
отмену движения пальцев и остановку последовательности при отказе action.
SSH `nssr-rtx6000` завершался таймаутом banner exchange и обрывом соединения.
Нативный A/B-прогон и обязательная проверка через `solution.sh` ожидают доступа
к стенду. PR остаётся draft до получения этих результатов.

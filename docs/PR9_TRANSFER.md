# Что перенесено из PR №9 в PR №23

Сравнение за 10 ноября 2026: опубликованный PR №9
`e499c89d092bf2c5f05a9975c05034cef11b3373` и PR №23 до исправления
`c20a35ce5e03d35501940a37f9b84f391be7b710`. Основа №23 — `main`
`f9ed0c0753c73d4121b66144bf8f9857e089db31`, включая PR №21 и №24.
После ревью также перенесена готовая offline-поставка весов из `assets/perception/`
того же PR №9. `run.sh` проверяет готовность bundle и предлагает Philips первым;
автоматическое включение осталось выключенным после неуспешной приёмки seed 7,
см. [ROADMAP](ROADMAP.md#pr23-review-20261110).

Незакоммиченные эксперименты в рабочей копии №9 не использованы.

Задача — взять предмет и положить в назначенный лоток. E71 — доказательство
подъёма и доноса Rhino, но не успешного раскрытия/размещения. Повторного поиска
захватов и обучения не было. Интеграционные прогоны 10 ноября описаны в ROADMAP.

## Потери и исправления

| Разница | До исправления №23 | Теперь |
|---|---|---|
| Рука не обязана совпадать со стороной лотка | Rhino справа → левый лоток отклонялся до контакта, хотя именно такой донос записан в E71. Philips/Nescafé имели тот же запрет | Выбирается доступная демонстрированная рука. Предпочтение стороне лотка сохранено, отключённая рука исключена. FSM может смотреть в противоположный лоток; зеркальных профилей не создаётся |
| Параметры placement из E71 request | Поворот потерян, использовались общие высоты 20/10 см | Для Rhino возвращены yaw −1.47215 рад, release 35 мм и approach +40 мм; bbox и TCP-offset поворачиваются вместе |
| Сначала подъём, затем перенос/поворот | При появлении отличной конечной ориентации старый carry начинал бы поворот уже на подъёме; fallback шёл прямо к конечной цели | Подъём сохраняет измеренную ориентацию. Перенос использует SLERP и аналитический минимум высоты всех вершин из №9. Повторяется только неудавшийся сегмент; нет прямого fallback через весь стол |
| Robot self-filter на экспозицию | Канонический RGB-D worker не имел фильтра №9. В E68 плечо уже создавало ложное препятствие | Перенесены spheres + 14 native visual hulls, exact/interpolated joint witness, reset/epoch checks, worker wiring и ограничение executor до двух потоков для этого режима |
| Остатки масок после фильтрации | Малые фрагменты объединялись в ложный объём и могли наследовать категорию исходной маски | Сохраняются все точки, раздельные компоненты и отрицательные ID/unknown; соседние реальные предметы не удаляются |

Пальцы E71, preshape, объектные TCP-трансформы и force 0.6 уже совпадали с
записью в №23. Они не заменены новым подбором. Подъём 12 см в штатной миссии
сохранён: 47 мм из E71 request — диагностическая проба, недостаточная для
штатного порога подтверждения подъёма 5 см.

## Как переиспользован код

Все перечисленные источники — из зафиксированного SHA №9 выше.

- `hack_grasp/geometry.py` → `hack_motion/recorded_geometry.py`, без изменения
  математики; `_minimum_rotating_support` из `hack_grasp/engine.py` →
  `recorded_carry.py`. Адаптер исполняет маршрут через существующий `MoveTcp`.
  Ограничение угла шага здесь 0.04 рад, поскольку основной planner проверяет
  отклонение от цели шага в пределах 0.05 рад. В №9 было 0.25 рад и другой
  проверяющий исполнитель. Это адаптация, не заявление об одинаковом timing.
- `rgbd_robot_filter.py`, `robot_self_mask.py`, `robot_visual_mask.py`, оба
  robot JSON и соответствующие регрессионные тесты переиспользованы напрямую.
  Импорт `session_geometry` заменён на `perception_robot_geometry`: из него
  извлечены только FK и measured spheres (`RobotGeometry` с `__init__`, `fk`,
  `tcp`, `hand_local`, `spheres`, `finger_commands` и необходимыми функциями).
  MotionSession, GPU-планировщик №9 и второй владелец приводов не добавлены.
- В `rgbd_response.py` перенесено только разделение disconnected/sparse
  компонентов. Held-surface tracking и depth-visibility протокол №9 не нужны
  текущему потребителю и не добавлены.
- ROS-адаптер и выбор двух потоков взяты из №9. Фильтр включается вместе с
  `recorded_grasps`; без него сохраняются восемь потоков обычного perception.
  Данные фильтра лежат в устанавливаемом пакете `hack_motion/robot`, без
  обращения к исследовательскому дереву или simulator state в runtime.

## Что не является потерянным исправлением этого пути

| Наработка №9 | Решение для №23 |
|---|---|
| Motor ownership, отмена, TF executor, обычные carry/ready и поправки main | Оставлен единственный владелец `main`; №23 уже основан на PR №21/#24. Session-протокол не накладывается поверх него |
| Dense-world cache 308 > 256 (`b974b19`), повтор preflight (`227eec4`), local IK, encoder-start replan, payload/OBB table lease | Исправляют `session_core/session_curobo` и dense observed world, отсутствующие в этом исполнителе. Копирование чисел в coarse world основного planner не воспроизведёт их смысл |
| Held-surface registration, depth-history exclusion, re-observation E51–E68 | Нужны собственному sensor-envelope исполнителю №9. Здесь остаётся основной PhysicalVerifier; равенство визуального отслеживания и collision coverage двух путей не заявляется |
| Сохранение направления головы после session approach (`95325ed`) | Связано с проверяемым head path в отдельном session. №23 заново запрашивает обе камеры перед спуском и останавливается без свежей позы. Автоматический поворот головы основного motion этим переносом не добавлен |
| Ослабление release gate (`17e6507`) | В №23 нет проверки вхождения uncertainty-inflated измеренной оболочки, остановившей E71. Есть предварительная проверка размера модели и независимая проверка после release. Убирать её или добавлять другой ложный gate не требуется |
| `visual_hold_policy=diagnostic` и более плотное закрытие (`e499c89`) | Не перенесены: опубликованы как ещё не проверенные native эксперименты. E72 потерял Rhino после подъёма; диагностическое продолжение не доказывает донос |
| Native PI/encoder bias, measured seating Brother | Не были частью ROS-исполнения E71. Это отдельные различия с исходными полными циклами коробок; они уже перечислены в `adaptations` профилей и не считаются исправленными |

№23 использует модель и неизменную связь предмета с кистью для расчёта укладки.
№9 использовал измеренный sensor envelope и повторные наблюдения вдоль маршрута.
Основной planner №23 не получил полного collision-envelope исполнителя №9;
скольжение, достижимость и время нового маршрута требуют полного стендового
цикла. Подъём/удержание отдельно не является приёмкой.

## Доказательства и проверка

- `tests/fixtures/rhino_e71_transfer.json`: компактная выборка из E71 trial02
  request/result с SHA256 исходников, канонической позой и левым лотком. Проверяет
  фактическую руку, профиль, force, yaw, release height, bbox в лотке и sweep.
  Сохраняет исходный результат `success=false`, `carry_completed=true`,
  `released=null`, а не превращает offline расчёт в физический успех.
- `native_shoulder_e68.json`: три измеренных случая плеча, 568/564/566 точек
  поверхности Rhino; фильтр удаляет плечо, ни одну из этих точек Rhino не удаляет.
  `native_body_measured_points135.json` сохраняет прежние 135 решений фильтра.
- Перенесён тест аналитического support с тем же seed 5917, включая минимум
  внутри дуги, которого нет в её концах. Основной FSM проходит тестовые миссии
  всех восьми профилей для лотков обеих сторон с явно заданной сенсорной evidence.
- Проверены disabled arm, отмена, stale TCP, отказ bounded fallback, строгий
  предел ориентации и для linear, и для direct, свежесть/эпоха RGB-D и соседние
  компоненты после фильтра.

Локально: 257 тестов, 249 прошли, 8 требуют ROS и пропущены; `check_rules`,
compileall и `git diff --check` проходят. Собраны wheel motion/perception;
вне исходного дерева загружаются все 8 профилей, 14 visual hulls и 50
измеряемых суставов геометрии робота. Исходные физические артефакты E71/E68
лежат в `outputs/grasp_pr9_live_20261108/` вне командного репозитория; компактные
fixtures находятся в PR. Сборка ROS и полный native/official цикл этой версии
не выполнены, поэтому PR остаётся draft. Запуск и критерии доноса описаны в
[RECORDED_SORT.md](RECORDED_SORT.md).

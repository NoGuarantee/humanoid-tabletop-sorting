## Реализовано

- `Clients` подключён к `/joint_states`, состояниям обеих Inspire-кистей и TF; sorting capability
  `verification` имеет реализацию. Успех action и `Hand.object_detected` доказательствами не являются.
- `ActionTransport` ждёт свежего покоя **после** terminal action: минимум три новых кадра,
  непрерывное окно ≥0.3 sim s, размах положений ≤0.004 rad для суставов. Старые, повторные,
  неполные и нечисловые кадры, разрывы >0.2 s не подтверждают остановку. Deadline ожидания — 2 sim s.
- Motion принимает отмену всех трёх actions, сериализует исполнение, проверяет отмену между
  командами/сегментами и заменяет цели измеренным удержанием при ошибке/отмене. Кисть не раскрывается
  автоматически. Длительный вызов планировщика не прерывается посередине; после его возврата
  отменённая операция не отправляет траекторию. При отсутствии terminal/измерений brain блокируется.
- После ошибки движения, завершившегося измеренным покоем, доступен настоящий `RECOVER`.
  Частично выполненный подъём может подтвердиться TF; при HOLDING без достаточного подъёма разрешён
  ограниченный повтор LIFT (не более `max_attempts` команд подъёма на объект).
- Перед спуском — `REFRESH_TARGET`: новая сцена, прежняя идентичность, смещение центра ≤2 cm.
  Задержки обнаружения сервисов и кадров после поворота головы ждутся ограниченно, без мгновенного
  расходования всего recovery budget. Разный порядок доставки `/clock` и кадров учтён.
- После RELEASE сначала RETREAT, затем VERIFY_PLACE. Подтверждённая укладка не выводится из
  открытия кисти или исчезновения предмета. Если отход не удался, `placed` не устанавливается.
- Штатный `done`: 3×0.2 wall s; fallback при ошибке конструктора: 10×0.5 wall s.
- Исправлено преобразование высоты кончиков пальцев в TCP: смещение 0.21 m вдоль локальной +z,
  локальная высота стола, направление закрытия по короткой стороне. Эти базовые исправления
  согласованы с конвенциями ветки команды `grasping/pick-one`; её экспериментальные пресеты не перенесены.

## Критерии verifier и ограничения

Окно кисти ≥0.3 sim s, размах ≤0.015, последний кадр не старше 0.2 s.
EMPTY: все приводы открыты ≥0.95; после попытки захвата — также достижение пустого пресета
с допуском 0.04. HOLDING: большой палец и хотя бы один противопоставленный палец остановились
на ≥0.05 выше заданного закрытия с effort >0.1; отсутствие effort не считается контактом.
При недостаточных данных ответ UNKNOWN. Эти пороги — инженерная эвристика, а не калиброванный
физический классификатор. Контакт с посторонним предметом/столом может дать ложный сигнал;
испытание по разрешённым данным и калибровка на реальной раскладке обязательны.

LIFTED требует контакта и измеренного увеличения z TCP ≥0.05 m от положения перед CLOSE.
При потере контакта/свежести повторное приписывание предмета кисти запрещено. Это косвенное
измерение подъёма: оно не заменяет визуальную верификацию движения самого объекта.

PLACED требует открытой/пустой кисти и **единственной именной** детекции нужного объекта после
отхода, confidence ≥min_confidence, без partially_visible; габаритный прямоугольник должен находиться
внутри наблюдаемого ящика с запасом 5 mm, высота соответствовать содержимому ящика.
Анонимный track_id после контакта не переименовывается по близости. Если текущий perception не
разделяет ящик и предмет, не распознаёт имя или кисть закрывает вид, размещение не подтверждается.
Нужны улучшения perception/смена взгляда, а не подмена проверки успехом команды.

Пробирки пока пропускаются до первого движения: нет реальной детекции штативов/гнёзд,
hood-transfer, вставки, переориентации и их верификации. Fake-покрытие tube-маршрутов не является
реализацией этих навыков. PR нельзя считать полностью физически готовым только по тестам ниже.

## Воспроизводимые проверки

Локально:

```bash
PYTHONPATH=src/hack_brain:tests python3 -m unittest discover -s tests
bash tools/check_rules.sh
git diff --check
```

На сервере: `colcon build --symlink-install --packages-up-to hack_brain` — успешно.
После сборки, **в отдельном ROS-домене**, без управления симулятором:

```bash
source install/setup.bash
export ROS_DOMAIN_ID=196 ROS_LOCALHOST_ONLY=1 PYTHONDONTWRITEBYTECODE=1
python3 tools/fsm_ros_smoke.py
python3 tools/fsm_cancel_smoke.py
```

Первый тест использует настоящий `Brain` (включая конструктор и поток миссии), `Clients`, ROS services/actions, TF и FSM с синтетическими
измерениями. Проверяет неудачный подход, измеренный покой, восстановление, захват, подъём,
перенос, release/retreat и визуальное подтверждение размещения. Не подставляет готовые Evidence.
Второй использует настоящий `MotionNode`: отмена MoveJoints, прекращение исходных команд,
измеренное удержание и освобождение ресурса transport только после свежего покоя.
Оба успешно выполнены на Descartes. Это middleware-тесты, не проверка физики или балла.

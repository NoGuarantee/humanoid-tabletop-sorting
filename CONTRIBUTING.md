# Как работаем

## Ветки и main

- **Проверяется последний коммит в `main`.** Поэтому `main` всегда должен собираться, запускаться и
  публиковать `/sim/task/done`.
- Работаем в ветках `<роль>/<что>`, например `motion/ik-pinocchio` или `perception/table-ransac`. В `main` попадаем через PR,
  который посмотрел хотя бы один человек.
- Перед PR: `bash tools/check_rules.sh` и прогон через `solution.sh` (см. ниже).
- Интерфейсы в `src/hack_interfaces` меняем только по договорённости всей команды: от них зависят все модули.

## Цикл разработки

Симулятор запускается в одном терминале, из корня репозитория симулятора:

```bash
bash hackathon/tools/task.sh sort3 --pool 4            # наш пул; --seed S для повторяемости
```

Во втором терминале запускается контейнер разработки с этим репозиторием в `/solution` (на запись):

```bash
NSSR_SIM=~/путь/к/nssr-uwt-polygon bash tools/dev_shell.sh
# внутри:
colcon build --symlink-install --build-base /tmp/b --install-base /tmp/i && source /tmp/i/setup.bash
ros2 launch hack_bringup solution.launch.py             # всё решение
ros2 run hack_motion motion_node --ros-args -p use_sim_time:=true   # или один узел
```

Сборка в локальном `dev_shell.sh` идёт в `/tmp` контейнера, поэтому в репозитории не появляются `build/` и `install/` с владельцем root. На сервере `remote.sh dev` собирает прямо в смонтированную копию (`colcon build --symlink-install` без `--build-base`): `build/` и `install/` остаются между запусками. У каждого `NSSR_WHO` своя копия и свой контейнер.

Отладка на стороне симулятора, из его репозитория:

```bash
bash hackathon/tools/task.sh check                     # сколько разложено
bash hackathon/tools/objects.sh randomize 5            # новая раскладка
bash hackathon/tools/viz_rviz.sh                       # облака точек и tf
```

## Проверка формата сдачи

При запущенном симуляторе, из репозитория симулятора:

```bash
bash hackathon/tools/solution.sh ~/путь/к/nssr-sol-team-049
```

Это та же установка и тот же запуск, что на финальной проверке. Если здесь не работает, не будет работать и там.

## Зависимости

- pip-пакеты пишем в `requirements.txt` **с версиями**. `numpy<2` уже есть в образе, не обновляем его.
- apt-пакеты пишем в `apt.txt`, по одному в строке.
- Веса моделей и всё большое скачиваем в `setup.sh`. В git файлы больше 100 МБ не кладём, при запуске интернета нет.

## Правила хакатона, которые легко нарушить случайно

- Не читать позы из симулятора и не зашивать заранее измеренные координаты стола, ящиков, штативов и шкафа: только
  камеры, глубина, энкодеры, датчики силы и состояние кистей. Примерные границы поиска, размеры из документации,
  `/sim/task` и геометрия робота допустимы.
- Не обращаться к `/sim/task/check`, `/sim/objects/set`, `/sim/objects/randomize` из `src/`. Отладочные скрипты
  кладём в `tools/`.
- Не копировать код других команд.

# Записанные захваты в штатной сортировке

Цель — взять предмет, поднять, перенести в назначенный задачей лоток, раскрыть
кисть и подтвердить размещение после отвода руки. Для этого подключены восемь
записанных профилей четырёх предметов к существующим `brain`, `Hand` и `MoveTcp`.
Отдельного исполнителя и пятисекундной выдержки в миссии нет.
Сравнение с PR №9 и перенесённые исправления: [PR9_TRANSFER.md](PR9_TRANSFER.md).

## Профили и исходные доказательства

| Предмет | Профили | Что подтверждено до этой интеграции |
|---|---|---|
| Brother | `brother_left_wide`, `brother_left_compact`, `brother_right` | 77/100 полных native-циклов в серии двух левых профилей; правый профиль из отдельного полного успешного `pick_brother0_v3` |
| Philips | `philips_right`, `philips_right_turn180` | 81/100 полных native-циклов исходной политики |
| Nescafé | `nescafe_right`, `nescafe_right_turn180` | 62/100 полных native-циклов исходной политики, включая точное продолжение двух случаев |
| Rhino | `rhino_e71` | E71: измеренный подъём 45.633 мм и перенос; раскрытие отклонено из-за выхода за край лотка на 12.903 мм, полного размещения нет |

Серии коробок относятся к исходным испытаниям в симуляции с известными позами.
E71 использовал RGB-D и отдельный исполнитель PR №9. Ни одно из этих чисел
не является результатом нового ROS-исполнения или официальным счётом. 10 ноября
доступ к `nssr-rtx6000` восстановлен: первый парный `eval` на seed 7 дал 2/9
для main и PR23, но Philips в PR23 не дошёл до движения из-за отсутствия
свежей канонической позы. На RTX 4090 свежесть и привязка позы затем прошли,
но спуск был отклонён planner. Это не подтверждение профиля; актуальные
результаты и артефакты перечислены в [ROADMAP](ROADMAP.md#pr23-4090-20261111).

Точные входы, отчёты и SHA256 каждого выбранного успешного случая перечислены
в `src/hack_motion/hack_motion/profiles/boxes.json`. Импортёр проверяет хеш
входа, соответствие отчёту и все проверки полного цикла, затем переводит позы
TCP в канонические координаты предмета. Связь с исходными координатами и шестью
командами кисти проверяется по `tests/recorded_grasp_sources.json`.

Архив исходных испытаний хранится отдельно от командного репозитория, под
`outputs/box_pose_robustness_20261107/` проекта `ros_hack`. Сводка —
`FULL_CYCLE_STATUS_v454.md`; политики — `brother_combo100_v187`,
`philips100_v224`, `coffee100_v215`; итог Nescafé —
`coffee100_combined_v435/verified_counts.json`. Для воспроизводимого импорта
при наличии этого архива:

```bash
python tools/import_recorded_boxes.py --project /path/to/ros_hack
```

Rhino сохранён из `e5da24ff94559913d3545d87e889f31fd71659c9`; хеши источников —
в `profiles/rhino_e71.json`. Локальные успехи других предметов — Peanut Butter,
Butter Rum, Jell-O, мыши и двуручных захватов — в этот адаптер пока не включены.

## Исполнение и границы переноса

`setup.sh` берёт включённый в исходники архив `assets/perception/geometry_only_ros_bundle.tar.gz`
из PR №9, проверяет SHA256, устанавливает зависимости и загружает PoseBackend на CPU.
Только после успешной проверки появляется `weights/.rgbd-ready`. Архив под `weights/`
имеет приоритет; при отсутствии обоих архивов доступна ограниченная загрузка
`NSSR_RGBD_BUNDLE_URL` (по умолчанию private release). Bundled-вариант не требует
GitHub-токена. Ошибка установки оставляет baseline и не меняет `exit 0` setup.

`run.sh` разрешает включение через `NSSR_RECORDED_GRASPS=true` только при ready
marker и manifest. **Автоматическое включение пока выключено:** seed 7 не
подтвердил полный цикл Philips. Для проверки: `bash run.sh recorded_grasps:=true`;
выбор по умолчанию — **только Philips**. Остальные предметы требуют явного выбора
через `NSSR_RECORDED_OBJECTS` или `recorded_objects:=brother`. Без готового bundle
окружение принудительно отключает recorded. Явные launch-аргументы имеют приоритет.
`NSSR_RECORDED_GRASPS=false` оставляет штатную сортировку; готовый RGB-D worker
в `run.sh` работает по запросу и не запускает фоновую подгонку моделей.
Допуск автоматического включения и незакрытая проверка описаны в ROADMAP.

При recorded-режиме 6D-позы рассчитываются по запросу только для семей из
`recorded_objects`; явный `rgbd_model_names` имеет приоритет. Это ограничение
дорогой подгонки моделей, не фильтр препятствий: остальные наблюдаемые
поверхности остаются в геометрии. Возраст принятой позы по-прежнему не более
1.75 секунды sim-time. Время расчёта, возраст результата и его принятие
пишутся в `rgbd_worker_timing`; brain сохраняет последнюю причину отказа.

`OPEN` и `DESCEND` асинхронно получают свежую позу именно выбранного предмета.
Ответ после отмены не запускает моторы. Перед спуском нужны новая экспозиция,
та же эпоха и изменение позы не более 2 см / 0.15 рад. Центр видимой части и
PCA-yaw не заменяют каноническую систему модели.

Лоток выбирается из `/sim/task`, рука — из записанных профилей. Если для стороны
лотка есть доступный профиль, он предпочтителен; иначе используется записанная
рука с другой стороны. Именно так E71 переносил Rhino правой рукой в `tray_left`.
Brother имеет варианты обеих рук; остальные три предмета — только правой.
Отключённая рука исключается и при выборе объекта, и при выборе профиля.
Автоматического зеркалирования нет. На второй попытке выбирается следующий
записанный вариант выбранной руки; перед спуском профиль уже не меняется.

В этом режиме включён `rgbd_robot_self_filter`: фильтр PR №9 удаляет только
точки известной геометрии робота, используя суставы и TF на экспозицию камеры.
При отсутствии согласованного измерения запрос ждёт следующий кадр. RGB остаётся
побитно исходным, удалённая глубина считается неизвестной. Загружаются 14
проверенных visual hulls рук и плеч; object CAD и сохранённые позы сцены не нужны.
Остатки разреженных масок сохраняются отдельными неизвестными препятствиями.

`Hand` отсчитывает расписание по `/clock`; отдельный watchdog останавливает
ожидание после 15 wall-секунд без продвижения `/clock`. Медленная, но идущая
симуляция не расходует общий wall-deadline закрытия.

`Hand` исполняет preshape и записанные шесть команд закрытия под общим motor
lock. Для коробок сохраняются конечные команды, длительность и одновременный
порядок закрытия; публикация идёт в 40 шагов вместо native 200. У Brother слева
раскрытие сначала разгибает пальцы, затем поворачивает большой палец. У Nescafé
после измеренного подъёма выполняется дополнительное поджатие и проверяется
сохранение контакта; неудача не разрешает перенос. Восстановление после сбоя
подъёма не пропускает эту фазу и не повторяет уже подтверждённое поджатие.

Позы и команды не воспроизводят весь native-контроллер: поправка encoder bias,
нативные суставные траектории, PI tracking и measured seating Brother не
перенесены. Укладка использует наблюдаемый лоток и штатное раскрытие над ним.
Для коробок ROS-лимит силы 0.6 — параметр первой проверки, а не доказанный
эквивалент native-силы. Эти различия записаны в `adaptations` профилей и требуют
отдельной проверки на стенде.

Для Philips восстановлен исходный запас переноса 15 см над краем лотка:
общие 20 см делают наклонённую кисть недостижимой на seed 7. Высота раскрытия
пока остаётся штатной, 10 см над краем; native-посадка возле дна не переносилась.
Во время `carry_fixed` отказ planner не переводит свободную руку в ready:
этот маршрут сбрасывает общий body yaw и поворачивает удерживаемый предмет.

Также различаются допустимые суставные положения. В исходном Philips
`philips100_v224_b4_s20000` модель, извлечённая из USD, допускает почти ±π
для запястья; хват использует правый wrist roll около −1.9 рад. Официальный
ROS-мост `robot_commands.Shaper` читает пределы из штатного URDF и обрезает
каждую команду: правый wrist roll не ниже −1.309 рад, wrist pitch не ниже
−0.785 рад. Это подтверждено кодом simulator `08247fc`, а не только описанием
интерфейсов. ROS-пределы не расширяются. Native-суставную траекторию нельзя
перенести буквально; нужен достижимый путь с одной из записанных поз кисти.

Philips выбирает между двумя существующими профилями по меньшему максимальному
горизонтальному вылету TCP при захвате и над лотком. Второй профиль остаётся
следующей попыткой; после OPEN профиль фиксируется до завершения попытки.
Это порядок проверки, не обещание достижимости. В диагностике seed 7 развёрнутый
профиль прошёл расчёт переноса и опускания с ROS-пределами; исходный профиль
упирался в пределы даже после проверки четырёх исходных вариантов поворота.

Ветка включает `main` на `f9ed0c0753c73d4121b66144bf8f9857e089db31`, уже с
изменениями переноса PR #21 и поправками PR #24. Подъём TCP — 12 см; контакт и
измеренный подъём проверяет прежний `PhysicalVerifier`.

Для размещения учитываются смещение предмета относительно TCP и весь bounding
box в осях лотка с запасом 15 мм. Перед контактом проверяется, что предмет
помещается, перед переносом расчёт повторяется по сцене назначения. Точка
раскрытия ставит низ предмета на заданную высоту над проёмом. Для Rhino
восстановлены параметры E71: yaw −1.47215 рад вокруг нормали лотка, низ предмета
на 35 мм над проёмом и подход ещё на 40 мм выше. Для коробок сохраняется
штатная высота; для Brother это пока отличается от посадки на дно в native-опыте.

Режимы `direct_fixed`, `linear_fixed`, `carry_fixed` сохраняют запрошенный yaw.
Линейные перемещения с фиксированной ориентацией раскладываются по мировым
осям: вертикальный спуск не превращается в боковой обход по осям наклонённой кисти.
`MoveTcp.action` дополнен необязательными `contact_object`, `contact_center`,
`contact_stamp_ns`. Их передаёт только recorded `DESCEND`: точный perception
track ID, центр сопоставленной модели и время новой RGB-D-экспозиции.
Motion проверяет свежесть, соответствие наблюдаемому объёму и короткий спуск
от измеренного TCP, затем разрешает контакт только с этим предметом.
Остальные предметы и стол остаются препятствиями; расширяющий разрешение
fallback отключён. Пустые поля сохраняют прежнее поведение main. Это заменяет
неподходящее для наклонённого силового хвата приближение кончиков пальцев
`TCP - 0.21 * TCP_z`, не меняя записанную позу или пальцы.
После изменения action нужно пересобрать все пакеты решения.

`carry_fixed`
берёт свежий измеренный TCP, поднимает без поворота и переносит с ограниченными
шагами SLERP: до 8 см / 0.04 рад. Высота учитывает самую нижнюю точку предмета
на всей дуге поворота, а не только в концах. Линейный и обходной путь каждого
шага проверяют на отклонение от короткой дуги между измеренным началом и целью:
не более `rot_tol` (0.05 рад) на каждой плановой точке. Сам поворот шага ограничен
0.04 рад плюс допустимая ошибка предыдущего завершения и 0.001 рад округления.
Сравнение только с конечной ориентацией ошибочно складывало эту ошибку с
намеренным поворотом и отклоняло допустимое продолжение. Контроль конечной
позы, столкновений и суставных пределов сохраняется.
Обход повторяет только текущий шаг; отмена и повторный отказ останавливают перенос.
Свободный yaw из обычного `carry` здесь изменил бы положение и габариты предмета
относительно цели. Обычные режимы продолжают работать по логике `main`.

После переноса идут `LOWER`, `RELEASE`, `RETREAT`, `CLEAR`, `VERIFY_PLACE`.
Успешный action не означает успешную сортировку: нужен контакт при переносе и
свежая проверка размещения после отвода руки. Геометрия предполагает отсутствие
скольжения в кисти; это ограничение пока не проверено новым физическим прогоном.
В лог пишутся предмет, профиль, рука, фаза, лоток, экспозиция и показания пальцев.

## Запуск и приёмка

Использовать собственный свободный слот и существующую среду по `SERVER.md`.
Локальная ветка — `grasp/rhino-profile-pick-20261110`, серверная копия —
`~/nssr/work/rhino-profile/nssr-sol-team-049`. Перед запуском записать SHA ветки,
версию RGB-D bundle, seed и проверить наличие моделей всех выбранных предметов.
Нужны модели канонических поз, а не только веса детекции. Фильтр моделей только
на Rhino для этого запуска не подходит.

Пример одного полного прогона (`--layouts 1` нужен для применения `--run`):

```bash
export NSSR_HOST=nssr-rtx6000
export NSSR_WHO=rhino-profile
bash tools/remote.sh status
bash tools/remote.sh gpu
bash tools/remote.sh eval sort3 --pool 4 --seed 13051 --layouts 1 --timeout 900 \
  --run 'bash run.sh recorded_grasps:=true recorded_objects:=brother,philips,nescafe rgbd_device:=cuda'
```

Для одного предмета задать, например, `recorded_objects:=brother`; для всех
четырёх — `rhino,brother,philips,nescafe`. У `rgbd_model_dir` должен быть путь
к подготовленному bundle внутри контейнера (обычный механизм проекта).
Остальные доступные предметы продолжают участвовать в штатной миссии.

Сравнить с `recorded_grasps:=false` на том же SHA и seed. После первого
сравнения повторить пару на seeds 7 и 146. Это ограниченная проверка интеграции,
не оценка надёжности на всех раскладках.

Сохранить полный лог, видео и свежий результат самопроверки с текущим `sim_step`.
Для каждого предмета записать профиль, руку, назначение, последний успешный
этап, место потери контакта, правильное размещение, штрафы и время. Приёмка:
предмет в правильном лотке, кисть открыта, рука отведена, положение независимо
подтверждено записью. Неизвестный или устаревший результат не считается успехом.

До сборки ROS и полного `solution.sh`/`eval` на стенде PR остаётся draft.
Включать профили по умолчанию следует по результатам полных доносов и сравнения
со штатным решением. Следующая правка должна отвечать конкретному отказу:
поза, подвод, закрытие, подъём, поджатие, перенос, раскрытие или проверка укладки.

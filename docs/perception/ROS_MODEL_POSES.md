# Оценка модельных поз через ROS

`hack_perception` может по запросу запустить RGB-D бэкенд из [PR #2, a3afb9b](https://github.com/nssr-hackathon/nssr-sol-team-049/tree/a3afb9b7fd3702403dc2615fd524afb01be13566/docs/perception/rgbd_review_20261105). В пакет перенесены инференс, сопоставление масок, регистрация облаков и проверка свободного пространства. Облака формы получены из RGB-D train с офлайн-разметкой. В рантайме используются зарегистрированные RGB и глубина с двух камер, их калибровки и `/tf`. Поддерживаются модели пулов 4 и 6 на столе.

Сервис подключается явно. `/perception/perceive` возвращает `SceneObjects` с кластерами, категориями и лотками. При подключённой модели высота стола и лотки оцениваются по зарегистрированному RGB-D на том же штампе. Если кадр или плоскость недоступны, сервис использует оценку по кластерам. Диагностический сервис даёт motion и perception временный контракт для проверки модельных поз перед согласованием типизированных полей в `DetectedObject`. Решение о повторном взгляде остаётся у вызывающего кода.

## Запуск

Скачайте [проверенный архив модели из релиза PR #2](https://github.com/nssr-hackathon/nssr-sol-team-049/releases/tag/pr2-rgbd-model-20261105) и распакуйте его на машине с ROS. Архив занимает 12,2 МБ. Бэкенд проверяет хеши весов и каждого облака при загрузке.

```bash
gh release download pr2-rgbd-model-20261105 -R nssr-hackathon/nssr-sol-team-049 \
  --pattern geometry_only_ros_bundle.tar.gz
echo 'b33b2debe3c1710bd6e7458b983767bfc7a7ce003b0d9c5560ad20ec5bd7fade  geometry_only_ros_bundle.tar.gz' \
  | sha256sum -c -
tar -xzf geometry_only_ros_bundle.tar.gz
```

В существующей среде решения с PyTorch 2.8.0 поставьте зависимости опционального режима. Сохраняйте NumPy 1.x, от которого зависит ROS Humble.

```bash
/usr/bin/python3 -m pip install 'numpy<2' scipy==1.11.4 opencv-python==4.11.0.86 \
  torchvision==0.23.0 ultralytics==8.3.40

colcon build --symlink-install --packages-up-to hack_perception
source install/setup.bash
ros2 run hack_perception perception_node --ros-args \
  -p use_sim_time:=true -p rgbd_model_dir:="$PWD/bundle_box"
```

По умолчанию `rgbd_pool:=0` берёт пул из официального поля `objects_from` в `/sim/task`. На стенде без метаданных можно передать `-p rgbd_pool:=4` или `-p rgbd_pool:=6`. Для полного launch задайте `NSSR_RGBD_MODEL_DIR` в окружении запуска. Оставьте каталог пустым для штатного режима. Если загрузка опциональной модели не удалась, узел пишет причину в лог и оставляет штатный сервис доступным.

```bash
ros2 service call /perception/estimate_model_poses std_srvs/srv/Trigger '{}'
# Укажите допустимый для вызывающего кода возраст кадра в секундах симуляции.
/usr/bin/python3 tools/perception_model_pose_check.py --max-age-s 3 --require-pose
```

## Контракт

Один вызов берёт последнюю общую экспозицию `cam_head` и `cam_torso`, не старше 1 с по часам узла **на входе**. Каждая камера должна передать `rgb8`, `16UC1` в мм и две `CameraInfo` с тем же штампом и совпадающими оптической рамкой, разрешением и матрицей K. Такое совпадение всех восьми штампов подтверждено в трёх сохранённых DDS-экспозициях. TF запрашивается в `pelvis` на штамп кадра. Кадры буферизуются ограниченно. При перемотке часов буфер и динамические TF очищаются. При смене метаданных задачи кадры сбрасываются. Для новой раскладки запускайте решение штатным отдельным процессом.

В `message` лежит JSON с `schema: "hack_perception.model_poses/v1"`, `status`, `frame_id: "pelvis"`, `stamp_ns`, `pool`, `table_z_m` и массивами `objects` и `containers`. `Trigger.success` означает, что обработана экспозиция. При общем отказе массивы пусты, а `status` объясняет причину, например `no_fresh_registered_pair` или `missing_exposure_tf`.

`containers` содержит наблюдаемые лотки с `id`, `kind: "tray"`, `color`, `center_pelvis_m`, `yaw_rad` (по модулю π) и `size_m`. По маске YOLO и измеренной глубине восстанавливается центр верхнего проёма. Координаты выдаются при достаточной видимости стенок. ID сопоставляется по цвету из `/sim/task`.

Плоскость стола оценивается по глубине после исключения масок YOLO. `table_z_m` в JSON даёт высоту плоскости при `x=y=0` в `pelvis` и принимает значение `0`, если кадр обработан, но плоскость не найдена. Типизированное поле `scene.table_z` даёт высоту при `x=0.38, y=0`, которую использует grasp planner.

У объекта указаны имя и категория, идентификаторы масок текущего кадра, число наблюдений глубины и остаток подгонки. `detector_score` служит для диагностики и отражает выход YOLO. Только при `pose_status: "ok"` возвращаются матрица `T_pelvis_object` и `center_pelvis_m`. Матрица переводит из рамки модели в `pelvis`. `orientation_mode` принимает `full`, `axis` (значимо направление локальной +Z), `c2` или `c4` (угол вокруг локальной Z с соответствующей симметрией).

| `pose_status` | Условие |
|---|---|
| `ok` | Две сопоставленные маски с ≥30 точками глубины на вид, хотя бы одна целая маска и подгонка прошла внутренний фильтр |
| `reacquire_single_view` | Поддержка есть только с одного ракурса, в том числе при обрезании его маски |
| `reacquire_clipped` | Обе поддерживающие маски касаются края кадра |
| `reacquire_uncertain_fit` | Остаток >12 мм, невалидная матрица или ненадёжное направление пробирки |
| `insufficient_depth` | Есть маска YOLO, но глубины для подгонки недостаточно |

Для движения проверяйте `pose_status` и возраст **исходного** `stamp_ns` после ответа. Объект и таз должны оставаться в состоянии экспозиции. При `reacquire_*` вызывающий код может сменить ракурс головы, дождаться остановки и повторить запрос, проверив новый штамп. Внутренние пороги диагностические. Требуются калибровка уверенности и проверка на кадрах с перекрытием кистями.

## Повтор и результат

Офлайн тот же бэкенд и JSON-адаптер запускаются на сенсорном манифесте PR #2.

```bash
PYTHONPATH=src/hack_perception python3 tools/perception_model_pose_replay.py \
  --model-dir "$PWD/bundle_box" --sensor "$SENSOR"
PYTHONPATH=src/hack_perception python3 -m unittest discover -s tests -v
bash tools/check_rules.sh
```

CPU на Mac, PyTorch 2.6.0 и Ultralytics 8.3.40. На трёх сохранённых парах Sort2 из двух раскладок (пулы 4 и 6) сервисный фильтр пропустил 12 оценок из 17. Все 12 матриц совпали с replay PR #2 на тех же ROS-входах. На соответствующих native-входах имена и статусы совпали, разница между модельными позами достигла 1,46 мм и 1,31° у часов. Инференс и сериализация одной пары занимали 1,04–1,44 с. В отдельно сохранённом кадре раковины `tmpbulk31_hw_v4-sort2-p4-none-01-000079` оценка скрыта с `reacquire_single_view`. Это пример отказа на известном промахе из ревью.

Открыты вызов сервиса в Linux с живыми ROS и симулятором, измерение нагрузки рядом с cuRobo, прогон `solution.sh` и проверка захвата.

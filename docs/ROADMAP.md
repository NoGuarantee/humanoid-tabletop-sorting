     `lookup_at` ждёт до 2 с времени симуляции, а если камера всё это время стояла, берёт последнюю позу.
   - Рука в позе `ready` над объектом склеивалась с ним в один кластер высотой 0,48 м, и тот отбрасывался как робот
     (коробка Philips). Точки выше 0,28 м над столом в кластеры больше не идут. Разбор одного кадра:
     `tools/perceive_dump.py`.
   - Для |y| до 0,52 нужен поворот головы по yaw, иначе крайние объекты обрезаны кадром.
   - `remote.sh check` иногда отдаёт устаревшее состояние, результат сверяем по видео.

     планировщика взят 3 из 3. Геометрию пальцев проверяем только прогонами.
   - Наклонный пинч на 45° для низких фигурок (божья коровка, носорог) в ветке не закоммичен: пальцы сомкнулись
     на объекте один раз, но он выскользнул на подъёме.
   - Коробки 6,4 см поперёк (Philips, Nescafe) вертикальной кистью не взяты ни разу за 22 попытки (2026-11-07).
     Пинч (указательный и большой) сжал Philips с обеих сторон, но коробка выскользнула на подъёме. Power, нацеленный

### План по захвату

Пул 4 закрыт, 9 объектов, поэтому параметры по объектам сами по себе не проблема. Проблема в том, что геометрию выводим
вручную и проверяем единичными прогонами: плоский пинч занимает примерно 300 из 516 строк `grasp_planner.py`, а мыльница
дает 1/9 балла `sort3`. Остальные объекты идут через два простых кандидата сверху, их прогонов в этом файле нет.

1. Отложить мыльницу и прогнать `tools/pick_one.py --object ...` на остальных 8 объектах без нового кода. Записать, что
   поднимается.
2. Для тех, что не поднялись, написать перебор в `tools/`: кандидаты из габаритов объекта (yaw, высота, смещение, пресет,
   сила), объект ставит `/sim/objects/set`, лучшее пишем в `grasp_db.yaml`. Это перебор из [ANALYSIS.md](ANALYSIS.md),
   раздел 7.2, переносим его с M3 сюда.
3. Проверять хват до подъёма: пальцы остановились и вырос `effort`. Если нет, брать следующего кандидата. Касание без
   подъёма стоит 0, а поднятый и оставленный вне ящика объект стоит −10.
4. В боевом прогоне не брать мыльницу, пока нет надежного хвата: 0 вместо возможных −10, потолок `sort3` 8 из 9. Код
   плоского пинча остается в ветке.

Если большинство из 8 объектов на шаге 1 не поднимется, проблема общая (пресеты, сила, высота): сначала чиним ее, потом
перебор. Обучаемые захваты не берем: в PR #4 43 успеха из 542 проб и 0 из 270 полных наборов на одной цели. Толчок
мыльницы к краю стола только в запасе. Параллельно чиним ящики в perception.

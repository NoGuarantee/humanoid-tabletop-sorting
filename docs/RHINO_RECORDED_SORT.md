# Записанный Rhino E71 в штатной сортировке

Цель профиля — донести Rhino до лотка его категории, раскрыть кисть и подтвердить
размещение после отвода руки. Сам по себе подъём или выдержка с предметом в кисти
не являются результатом сортировки. Потеря поднятого предмета может стоить −10.

## Как работает интеграция

Обычный `run.sh` запускает прежние motion, perception и brain. Параметр
`recorded_grasps:=true` включает Rhino E71 в том же списке кандидатов `brain`
и включает сервис канонических RGB-D-поз. Остальные профили не меняются.
По умолчанию Rhino остаётся `skip` до подтверждённых полных доносов.

`OPEN` и `DESCEND` запрашивают свежую позу канонической модели. Операция ждёт
её в пределах обычного бюджета сцены, не блокируя ROS callbacks. Ответ после
отмены не запускает движение. Перед спуском проверяется общность эпохи и
ограничивается изменение позы относительно подвода. Центр видимой части и
PCA-yaw не используются вместо канонической системы профиля.

Штатный `Hand` открывает пальцы и задаёт preshape, затем выполняет записанное
закрытие под общим motor lock. Штатный `MoveTcp` поднимает TCP на 12 см по
плану, далее `brain` проверяет контакт и измеренный подъём. Отдельной
пятисекундной выдержки нет.

Лоток выбирается существующей политикой из `/sim/task.categories`. Профиль
проверен только для правой руки: назначение, требующее левую руку, отклоняется
до контакта. Зеркальный хват автоматически не строится.

В расчёте укладки сохраняются ориентация кисти и смещение центра предмета
относительно TCP. Полный bounding box канонической модели проверяется в осях
наблюдаемого лотка. Точка сброса смещается к роботу только в пределах места,
доступного всему предмету с запасом 15 мм. Заведомо тесный лоток отклоняется
до захвата, а перед переносом геометрия пересчитывается по сцене назначения.

Далее идут существующие `TRANSFER` (`carry`), `LOWER`, `RELEASE`, `RETREAT`,
`CLEAR` и `VERIFY_PLACE`. Контакт во время переноса и размещение после раскрытия
проверяет прежний `PhysicalVerifier`. Action success не объявляет предмет
размещённым. Геометрия предполагает, что предмет не сдвинулся в кисти: это ещё
нужно проверить в симуляции, вместе с collision world и достижимостью.

PR #21 остаётся отдельной работой команды. Его изменения в этот PR не скопированы.
Сравнение с результатами `5ff6fda` проводить на общем базовом коде с этим переносом:
после его слияния обновить ветку и записать новый SHA. На старом main остаются
его прежние ограничения `carry`, включая запасной `direct`.

## Ограниченный прогон и приёмка

Использовать собственный свободный слот стенда и существующую среду по
`docs/SERVER.md`. Код — эта ветка, серверная копия —
`~/nssr/work/rhino-profile/nssr-sol-team-049`. До запуска записать SHA, состояние
PR #21, версию RGB-D bundle и seed. Веса брать из штатного staged bundle.

Пример одного полного прогона; `--layouts 1` нужен для применения `--run`:

```bash
export NSSR_HOST=nssr-rtx6000
export NSSR_WHO=rhino-profile
bash tools/remote.sh status
bash tools/remote.sh gpu
bash tools/remote.sh eval sort3 --pool 4 --seed 13051 --layouts 1 --timeout 900 \
  --run 'bash run.sh recorded_grasps:=true rgbd_device:=cuda rgbd_model_names:=Schleich_African_Black_Rhino'
```

Для контроля выполнить тот же `run.sh` на той же версии с
`recorded_grasps:=false`, затем повторить пару на seeds 7 и 146. Одинаковыми
должны быть исходная раскладка, перенос, perception и настройки среды. Это
первая ограниченная серия, не оценка надёжности на всех раскладках.

Для каждого прогона сохранить полный лог миссии, видео, свежую итоговую
самопроверку стенда с текущим `sim_step` и распределение предметов. Метрики:
правильные размещения, штрафы, время, последний успешный этап для Rhino и
место потери контакта при неудаче. Успех Rhino требует правильного лотка,
открытой кисти, отвода руки и независимого подтверждения по записи. Устаревшая
самопроверка или скрытый камерой предмет оставляют результат неизвестным.

Снять `skip` по умолчанию можно после нескольких полных доносов подряд и
проверки, что изменение не ухудшило остальных предметов на тех же seeds.
До этого PR остаётся draft. Следующее изменение выбирается по конкретному
срыву: получение позы, подвод, закрытие, подъём, перенос, раскрытие или
подтверждение размещения. Повторять всю цепочку с произвольной настройкой
пальцев без локализации отказа не требуется.

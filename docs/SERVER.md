# Сервер с GPU

Симулятор и решение работают на арендованном сервере. Код, git и ключи остаются на ваших машинах, сервер только
запускает. С сервером работаем через [tools/remote.sh](../tools/remote.sh): он копирует рабочее дерево и выполняет
команды по ssh. Так же работают и агенты.

Почему агенты не живут на сервере: хост на vast.ai — посторонний человек с root на железе, а инстанс одноразовый.
Ключей с правом пуша на сервере нет, и всё ценное лежит в git.

## Какой сервер брать

Итоговая проверка идёт на RTX 5080 16 ГБ и 32 ГБ ОЗУ ([ANALYSIS.md](ANALYSIS.md), раздел 1).

| Параметр | Что брать | Почему |
|---|---|---|
| Тип на vast.ai | **VM** (фильтр хостов с VM), шаблон «Ubuntu 22.04 VM» или «Ubuntu Desktop (VM)» | обычный инстанс сам контейнер, Docker внутри запрещён |
| GPU | RTX 5080 16 ГБ, если нет — 5090 | та же архитектура Blackwell (sm_120), что на проверке; A100 и H100 не подходят, нет RT-ядер |
| Диск | 150–200 ГБ | после создания не меняется; образ около 30 ГБ, кэш, rosbag, датасеты |
| RAM, CPU | от 32 ГБ, 8+ ядер с высокой частотой | физика и ROS на CPU |
| Драйвер | 580+ | требование организаторов |
| Хост | надёжность от 99%, on-demand | interruptible могут забрать |

После остановки инстанса видеокарту может занять другой арендатор. Новый сервер поднимается заново
скриптом `tools/server_setup.sh`.

## Первая настройка (один человек)

1. **ssh.** У себя в `~/.ssh/config` (адрес и порт из карточки инстанса на vast.ai):
   ```
   Host nssr
     HostName 1.2.3.4
     Port 41234
     User root
     ControlMaster auto
     ControlPath ~/.ssh/cm-%r@%h-%p
     ControlPersist 10m
   ```
   `ControlMaster` держит одно соединение, и команды агента не ждут новое рукопожатие.
2. **Токен GitHub только на чтение.** Ассеты симулятора скачиваются через `gh` из закрытого репозитория. Создайте
   fine-grained token: Settings → Developer settings → Fine-grained tokens, владелец `nssr-hackathon`, репозитории
   `nssr-uwt-polygon` и `nssr-sol-team-049`, права `Contents: Read-only`. На сервере:
   ```bash
   ssh nssr
   gh auth login --with-token <<< 'github_pat_...' && gh auth setup-git
   ```
   Если `gh` ещё не стоит, сначала запустите шаг 3: он поставит `gh` и остановится на этом месте. Классический токен
   со scope `repo` даёт полный доступ ко всем вашим репозиториям, его на сервер не кладём. Если организация не
   разрешает fine-grained токены, обойдёмся без GitHub на сервере: скопируйте свой клон симулятора в
   `~/nssr/nssr-uwt-polygon` через rsync, а архив ассетов с релиза распакуйте командой
   `bash hackathon/tools/get_assets.sh путь/к/архиву`.
3. **Настройка сервера.** Со своей машины: `bash tools/remote.sh setup`. Скрипт ставит Docker, NVIDIA Container
   Toolkit, tmux и gh, клонирует симулятор, скачивает ассеты, собирает образ (около 10 минут) и проверяет контейнер.
   Повторный запуск пропускает готовые шаги. Лог: `~/nssr/logs/setup.log` на сервере.
4. **Проверка.** `bash tools/remote.sh eval sort3 --pool 4`: прогон как на проверке, в конце самопроверка.

## Каждому участнику

- Тот же `Host nssr` в `~/.ssh/config` и свой публичный ключ в `~/.ssh/authorized_keys` на сервере.
- По желанию `.remote.env` в корне репозитория (в git не попадает): `NSSR_HOST=nssr`, `NSSR_WHO=имя`. По умолчанию
  имя берётся из `git config user.name`. Под этим именем у вас своя папка на сервере и запись в замке.

## Команды

| Команда | Что делает |
|---|---|
| `remote.sh sync` | копирует рабочее дерево в `~/nssr/work/<имя>/` без коммита, `.gitignore` учитывается |
| `remote.sh eval sort3 --pool 4 [--seed S]` | sync, симулятор, `solution.sh`, ожидание `/sim/task/done` и выхода `run.sh`, самопроверка, остановка. `--keep` оставляет всё запущенным, `--timeout S` |
| `remote.sh eval sort3 --pool 4 --layouts N` | Как на проверке: установка один раз, затем `run.sh` в чистом контейнере на каждой из N раскладок одного симулятора. Раскладки меняет отладочный `randomize`, логи в `logs/solution.layoutI.log`, `--timeout S` на раскладку |
| `remote.sh sim start sort3 --pool 4` / `sim stop` | симулятор в tmux на сервере, ждёт публикации `/sim/task`. Без экрана запускается с `--headless` |
| `remote.sh solution` / `solution wait 600` / `solution stop` | `solution.sh` из вашей копии, как на проверке |
| `remote.sh dev -- 'colcon build --symlink-install && ros2 run …'` | команда в свежем контейнере из образа, ваша копия смонтирована в `/solution`; быстрее, чем полная установка `solution.sh` |
| `remote.sh ros ros2 topic list` | команда ROS 2 в контейнере симулятора, таймаут 20 с |
| `remote.sh check` | самопроверка `/sim/task/check` (только отладка, в `src/` нельзя) |
| `remote.sh logs sim\|solution\|setup [N]` | хвост лога |
| `remote.sh gpu` | VRAM, RAM, контейнеры против бюджета 16 ГБ и 32 ГБ |
| `remote.sh status` | кто занял стенд, что запущено |
| `remote.sh fetch logs/solution.log` | скачать файл или папку из `~/nssr` в `.fetch/` (кадры, rosbag) |

**Стенд один.** На видеокарте помещается один симулятор, ROS-домен и имя контейнера решения общие. Поэтому
`sim start` занимает стенд за вами (`~/nssr/bench.lock`), а `sim stop` освобождает. Чужой стенд `sim start`
не перехватит без `--force`; прежде чем так делать, спросите в чате. Если стенда не хватает, арендуем второй сервер.

**Окно Isaac и скринкасты.** Через `remote.sh` симулятор идёт без экрана. Для окна симулятора нужен шаблон
«Ubuntu Desktop (VM)»: запустите `task.sh` руками из сессии рабочего стола.

# Стол, лотки и модельные позы через ROS

Штатный `/perception/perceive` может дополнять `SceneObjects` измеренной высотой стола и центрами проёмов лотков. Лотки определяются по YOLO-маскам, глубине и цвету пластика. ID берутся из официального соответствия цвета и лотка в `/sim/task`. Если модель не нашла часть лотков, их ID дополняются из штатного цветового детектора, в том числе при найденной плоскости и пустом списке лотков. Кластеры объектов и их категории по-прежнему выдаёт штатный детектор. `brain` и `hack_interfaces` используют прежний контракт.

Опциональный 6D-режим использует [инференс из PR #2, a3afb9b](https://github.com/nssr-hackathon/nssr-sol-team-049/tree/a3afb9b7fd3702403dc2615fd524afb01be13566/docs/perception/rgbd_review_20261105) для пулов 4 и 6. Облака формы получены из RGB-D train с офлайн-разметкой. Режим выдаёт временный диагностический JSON до согласования типизированных полей `DetectedObject`. Для включения на сдаче требуется решение команды о допустимости артефактов обучения.

## Подготовка и запуск

По умолчанию архив отсутствует и решение запускает штатный детектор. Чтобы проверить opt-in в Linux, скачайте [пакет из приватного релиза PR #2](https://github.com/nssr-hackathon/nssr-sol-team-049/releases/tag/pr2-rgbd-model-20261105) с машины, где уже есть доступ к репозиторию. Архив весит 12,2 МБ. При запуске нужен только локальный пакет.

```bash
mkdir -p weights
gh release download pr2-rgbd-model-20261105 -R nssr-hackathon/nssr-sol-team-049 \
  --pattern geometry_only_ros_bundle.tar.gz --dir weights
bash tools/stage_perception_rgbd.sh
```

Скрипт сверяет SHA-256 архива `b33b2debe3c1710bd6e7458b983767bfc7a7ce003b0d9c5560ad20ec5bd7fade` и распаковывает пакет в `weights/rgbd-b33b2debe3c1`. Воркеры дополнительно проверяют хеши загружаемых весов и, в режиме 6D, каждого облака. При `tools/remote.sh sync` положите архив отдельно в каталог `weights/` удалённой копии, так как синхронизация исключает этот каталог.

Для `solution.sh` архив должен лежать в `weights/` дерева, которое копируется в контейнер. При его наличии `setup.sh` сверяет и распаковывает архив, устанавливает версии из `tools/perception_rgbd_requirements.txt` после PyTorch 2.8.0 и проверяет импорты с NumPy 1.x. Маркер успешной подготовки включает воркер стола и лотков в `run.sh`. Скачивание архива выполняет оператор до подготовки. Воркеры отключают сетевую проверку и автоустановку Ultralytics. Для включения 6D передайте launch-аргумент `rgbd_enable_model_poses:=true`.

На стенде с установленным PyTorch 2.8.0 можно запустить только узел perception.

```bash
/usr/bin/python3 -m pip install 'numpy<2' -r tools/perception_rgbd_requirements.txt
colcon build --symlink-install --packages-up-to hack_perception
source install/setup.bash
ros2 run hack_perception perception_node --ros-args -p use_sim_time:=true \
  -p rgbd_model_dir:="$PWD/weights/rgbd-b33b2debe3c1" \
  -p rgbd_enable_model_poses:=true
```

Пул берётся из `objects_from` в `/sim/task`, на изолированном стенде его можно задать `-p rgbd_pool:=4` или `-p rgbd_pool:=6`. Параметр `rgbd_torch_threads` задаёт 1–4 CPU-потока Torch в воркере, по умолчанию 2. При ошибке инициализации, завершении или превышении лимита времени воркера штатный детектор остаётся доступным.

## Буфер, возраст и контракты

У узла одна надёжная подписка на каждый используемый поток с DDS `KEEP_LAST` глубины 2, как у официального моста. В режиме модели добавляется `depth/camera_info` для каждой камеры. Одна экспозиция камеры требует одинаковых заголовков, разрешения и K для RGB `rgb8`, глубины `16UC1` в мм и двух `CameraInfo`. Два ракурса объединяются только по общему штампу. TF запрашивается на время экспозиции в `pelvis`. Если общей экспозиции нет, воркер может обработать одну камеру.

CPU-воркер работает отдельным процессом, принимает последний доступный кадр возрастом до 0,35 с, запускает не более трёх вычислений геометрии в секунду реального времени и держит одно вычисление в работе. Узел использует последнюю готовую сцену вместе с исходным кадром того же штампа. `Perceive` не ждёт результата воркера. При отсутствии свежей сцены или плоскости он использует штатный RGB-D путь. В opt-in режиме ответ `Perceive` ограничен возрастом экспозиции 1 с по часам симуляции. `SceneObjects.table_z` относится к точке стола `(0.38, 0)` в `pelvis`. При перемотке часов или смене метаданных задачи сбрасываются результаты, кадры обоих путей и трекер. При перемотке также очищаются динамические TF. Для новой раскладки запускайте решение отдельным процессом.

Опциональный `/perception/estimate_model_poses` (`std_srvs/Trigger`) использует кэш масок и плоскости того же штампа. Первый вызов запрашивает вычисление, пока воркер занят возвращается `awaiting_fresh_pose`. Для 6D достаточно свежей экспозиции одной камеры. Когда доступна синхронная пара, используются оба ракурса. Возраст к моменту постановки 6D в работу ограничен 0,65 с, к моменту ответа 1,75 с. Кэшированный результат может возвращаться повторно до истечения срока. Клиент после движения проверяет, что `stamp_ns` новее движения и укладывается в его бюджет.

В `message` лежит JSON с `schema: "hack_perception.model_poses/v1"`, `status`, `frame_id: "pelvis"`, `stamp_ns`, `pool`, `table_z_m`, `objects` и `containers`. В диагностике `table_z_m` измерен в точке `(0, 0)`. `Trigger.success` означает, что готова свежая оценка экспозиции. Матрица `T_pelvis_object` и `center_pelvis_m` возвращаются только при `pose_status: "ok"`. `orientation_mode` принимает `full`, `axis` (значимо направление локальной +Z), `c2` или `c4`. `detector_score` отражает выход YOLO.

| `pose_status` | Условие |
|---|---|
| `ok` | Хотя бы один ракурс с ≥30 точками глубины и целой маской, подгонка прошла внутренний фильтр. Число поддерживающих ракурсов указано в `depth_supported_views` |
| `reacquire_clipped` | Все поддерживающие маски касаются края кадра |
| `reacquire_uncertain_fit` | Остаток >12 мм, невалидная матрица или ненадёжное направление пробирки |
| `insufficient_depth` | Есть маска YOLO, но глубины для подгонки недостаточно |

При `reacquire_*` вызывающий код может сменить ракурс головы, дождаться остановки и запросить новую экспозицию. Порог пригодности для захвата требует проверки на стенде.

## Проверки

```bash
PYTHONPATH=src/hack_perception python3 tools/perception_model_pose_replay.py \
  --model-dir "$PWD/weights/rgbd-b33b2debe3c1" --sensor "$SENSOR"
PYTHONPATH=src/hack_perception python3 -m unittest discover -s tests -v
bash tools/check_rules.sh
```

- 18 тестов. Проверены, среди прочего, отклонение кадра из старой эпохи, повторное использование масок, сохранение согласованного кэша после ошибки, fallback лотков, порядок классов YOLO и геометрия лотков с обрезанием. Проверка архива и выбор opt-in пути в `run.sh` выполнены локально.
- Три сохранённых DDS-пары Sort2 из двух раскладок (пулы 4 и 6) прогнаны через отдельный процесс на Mac. Таблица измерена на всех трёх парах. Лотки найдены в числе 0, 1 и 1 в каждом из двух режимов. Стол и лотки занимали около 0,08–0,09 с на прогретых парах и 0,40–0,57 с на первом кадре. 6D после готовых масок и плоскости занимал 0,69–1,33 с. В это время локальная депроекция и кластеризация в родительском процессе занимали 0,021–0,043 с. Здесь измерены CPU этапы без DDS и ROS callbacks.
- До разрешения однокамерной оценки на этих DDS-парах 12 оценок прошли фильтр, 5 однокамерных отклонены. Сравнение с предыдущим head PR #5 на тех же входах подтвердило имена и статусы всех 17 детекций. При переходе на общую измеренную плоскость максимальный сдвиг у принятых объектов достиг 1,30 мм и 1,17° по полной ориентации у часов. У осевой миски изменился поворот вокруг её оси, направление оси отличалось на 0,0034°. Среди отклонённых тогда была раковина из кадра `tmpbulk31_hw_v4-sort2-p4-none-01-000079`.
- На 56 архивных native-парах Sort2/Sort3 из 14 раскладок с сохранёнными масками найдено 58 из 101 видимого наблюдения лотков. За несколько ракурсов покрыты 32 из 32 видимых комбинаций раскладки и лотка. Для 58 найденных проёмов P95 ошибки центра составил 3,53 мм, yaw 1,00°. P95 ошибки высоты стола в точке `(0.38, 0)` составил 0,11 мм. Разметка использована офлайн для подсчёта ошибок.

## Приёмка на живом стенде

Запустите Sort3, pool 4, после команды головы на штатный взгляд сразу вызовите проверку. Для сравнения повторите с выключенной моделью и с недоступным каталогом весов. Для проверки параллельной 6D работы включите `rgbd_enable_model_poses` и запустите клиент без `--scene-only`. Он вызывает `Perceive`, пока запрошена 6D оценка, и записывает задержку и возраст каждого ответа.

```bash
/usr/bin/python3 tools/perception_model_pose_check.py --scene-only --require-first-tray
/usr/bin/python3 tools/perception_model_pose_check.py --require-first-tray --require-pose
ros2 topic info /cam_head/color/image_raw --verbose
```

Первый ответ после `LOOK_TABLE` критичен, поскольку текущий `brain` завершает сортировку, если подходящих объектов и лотков в нём нет. На живом стенде остаётся проверить первый взгляд, задержки DDS, нагрузку рядом с cuRobo, запуск через `solution.sh` и захват. Понадобится решение команды по облакам из RGB-D train и согласованию полей `DetectedObject`.

# Видео из симулятора

Ролик — это цветные кадры робота, не окно Isaac. `remote.sh` поднимает симулятор с `--headless`, экрана нет, репозиторий симулятора только для чтения. Камеры: `/cam_head/color/image_raw` и `/cam_torso/color/image_raw`, 640×360, `rgb8`, QoS reliable depth 2.

Скрипт [scripts/record_cameras.py](scripts/record_cameras.py) клеит камеры в один mp4. Секунда ролика — секунда `/clock`, поэтому медленный симулятор не растягивает видео. Пиши его через `remote.sh dev`: там есть ROS, общий DDS (кадры идут через shared memory) и длинный таймаут. `remote.sh ros` обрывается через 20 с и для записи не годится.

Файл кладётся в `log/video/` на сервере (каталог в gitignore). Локально он появляется только после `fetch`, в `.fetch/`. В git mp4 не коммитить.

## Прежде чем занять стенд

`bash tools/remote.sh status`.

- Замок на чужом имени — остановись и скажи человеку. `--force` не используй.
- Симулятор уже наш — не делай `sim start` и `eval`: оба сбрасывают раскладку.
- Пока идёт запись, не запускай второй `remote.sh dev`: он убивает предыдущую команду в `nssr-dev-<имя>`, вместе с рекордером. `solution`, `logs`, `status`, `fetch` можно.

## Прогон целиком

Рекордер должен подписаться до старта решения: `/sim/task/done` не latched, опоздавший подписчик конец прогона не увидит.

1. Если симулятор не запущен и стенд свободен или наш: `bash tools/remote.sh sim start sort3 --pool 4` (задача и сид — как попросил человек; пул по умолчанию 4).
2. В фоне, таймаут больше ожидания решения:

```bash
bash tools/remote.sh dev --timeout 1000 -- \
  'python3 .cursor/skills/sim-video/scripts/record_cameras.py --out log/video/sort3.mp4 --until-done --seconds 900'
```

3. Дождись строки `recording ...`. Её нет за пару минут — смотри вывод, не стартуй решение вслепую.
4. `bash tools/remote.sh solution`, затем `bash tools/remote.sh solution wait 600`.
5. Дождись строки `wrote ...`. По ней рекордер сам вышел: `done` или лимит `--seconds`. Не убивай процесс, пока файл не закрыт: mp4 дописывается при выходе.
6. Имя из `status` (`you:`):

```bash
bash tools/remote.sh fetch work/<who>/nssr-sol-team-049/log/video/sort3.mp4
```

Отдай человеку путь `.fetch/sort3.mp4` и сколько секунд симуляции в ролике (цифра из `wrote`).

`--seconds` — запасной предел по времени симуляции, чтобы файл закрылся, даже если решение не опубликует `done`. `--timeout` у `dev` держи больше этого предела: внешний timeout шлёт SIGTERM, скрипт на нём тоже закрывает файл, но чистый выход надёжнее.

## Уже идущая сцена

Решение или симулятор уже работают и их нельзя перезапускать — пиши кусок, без `--until-done`:

```bash
bash tools/remote.sh dev --timeout 120 -- \
  'python3 .cursor/skills/sim-video/scripts/record_cameras.py --out log/video/clip.mp4 --seconds 15'
```

`--until-done` имеет смысл только если `done` ещё впереди. Снятый после конца прогона флаг ничего не ждёт и упирается в `--seconds`.

Одна камера: `--cameras head` или `--cameras torso`.

## Если кадров нет

Скрипт пишет в stderr и выходит с кодом 1. Частые причины: симулятор не в статусе running, процесс запущен не в dev-контейнере (другой DDS — кадров не видно), `HACK_CAMS` выключил одну камеру. Второе лечится повторным запуском именно через `remote.sh dev`, а не локальным python.
